## Evidence-backed design anchors

1. **Repo-local execution and PR delivery.** Claude Code can edit files, run commands, create branches, and open PRs. Therefore the workflow is stored as repo files and requires branch+PR output, not chat-only instructions.
2. **PreToolUse hook gate.** Claude Code hooks support lifecycle events including `PreToolUse`; hook handlers can inspect input and return a deny permission decision. Therefore wrong-tool prevention belongs in hook-compatible policy and scripts.
3. **Specialized subagents.** Claude Code supports built-in read-only Explore/Plan subagents and custom subagents with tool restrictions. Therefore this workflow separates discovery, implementation, and SAR review roles.
4. **GitHub Actions execution.** Claude Code GitHub Actions can implement code from issues/PRs and follows project standards. Therefore the pack includes CI/PR acceptance gates and a GitHub Actions readiness path.
5. **Secure development and recurrence prevention.** NIST SSDF says secure software practices reduce vulnerabilities, mitigate impact, and address root causes to prevent recurrence. Therefore repeated-blocker detection must route to RCA instead of allowing repeated retries.
6. **Provenance and reproducibility.** SLSA provenance describes where, when, and how artifacts were produced and supports rebuilding/verification. Therefore this workflow requires receipts, digests, command ledgers, and source-to-output binding.
